# 🏰 Arknights Self-Host Hub (明日方舟多账号低功耗自托管服务)

> **“让罗德岛的日常运转，静默发生在一台几瓦功耗的小主机里。”**  
> 这是一个专为低功耗 Linux 家用服务器打造的、带现代化 Web 控制面板的明日方舟全自动多账号托管平台。

---

## ☕ 写在前面：为什么做这个？

身为罗德岛老博士，每天重复上线清智、换班、公招、逛信用商店，时间久了难免疲惫；可如果交给第三方的收费托管平台，密码和 Token 托管在别人的服务器上，总归让人悬着一颗心。

我们往往开着家里的 Windows 主机挂模拟器跑 MAA，不仅风扇呼呼转、机箱呼呼发热，一个月下来电费账单也不好看。

其实，很多小伙伴家里都常年开着一台小主机——可能是一台闲置的工控机、软路由、J4105/N5105/N100 小盒子，或者是私人 NAS。**既然它 24 小时通电待命，为什么不让它来替我们值守罗德岛呢？**

这个项目就是为了解决这个痛点而生：**极低资源占用、按需自动唤醒模拟器、任务跑完彻底释放内存、多账号完全物理隔离、自带 Web 交互投屏与物资大屏。**

## 🎯 适用人群与项目定位

### 适合你，如果：
1. **家里有闲置或常开的低功耗 Linux 小主机**（软路由、迷你主机、NAS、工控机等）。
2. **拥有多个明日方舟账号**（自己大号 + 小号，或者帮朋友/亲友一起托管）。
3. **注重隐私与账号安全**，绝不希望将游戏账密或敏感 Token 上传至公共云端。
4. **追求“零感省心”**：设定好每天的排班时段与理智关卡，每天只在微信里看一张漂漂亮亮的收成战报。

### 项目定位：
一个 **轻量、低门槛、模块化、高安全性** 的个人/家庭私有化 MAA 托管服务，让你彻底告别开着笨重 PC 挂模拟器的日子。

## ⚡ 性能占用与硬件要求 (真实的生产数据)

我们非常讨厌“动不动就要 16 核 32G 独立显卡”的笨重架构。以下是作者在自己家用小主机上的**真实生产环境实测数据**：

### 🛠️ 作者小主机实测配置
* **CPU**: Intel® Celeron® J4105 @ 1.50GHz (4 核 4 线程，**整机 TDP 仅 10W**)
* **内存**: 12GB DDR4
* **系统环境**: Ubuntu 22.04 LTS (Linux 内核 5.15)

### 📊 真实资源开销对比
| 运行状态 | CPU 占用 | 内存实际开销 | 说明 |
| :--- | :--- | :--- | :--- |
| **日常待机 (99% 时间)** | **0.03%** | **~20 MB** | 仅运行极简 Web 控制面板，安卓模拟器完全处于休眠停止状态，几乎不耗电 |
| **定时流水线执行中** | 15% ~ 35% | 1.8 GB ~ 2.5 GB | 模拟器按需拉起，执行 MAA 图像识别、换班与作战，全程无卡顿 |
| **任务结束即刻** | **秒级归零** | **完全释放** | 流水线退出后自动关闭 ReDroid 容器，内存回归空闲 |

### 💻 建议最低运行配置
* **处理器**: 2 核及以上 64 位 x86_64 或 ARM64 处理器
* **内存**: 最低 **4GB RAM**（推荐 8GB，多账号轮转更从容）
* **存储**: 预留 25GB 以上可用空间（用于存放安卓系统镜像与游戏本体资源）
* **内核要求**: Linux Kernel ≥ 5.4，需支持 `binderfs`（绝大多数现代 Ubuntu/Debian 均已默认原生支持）

## 🧩 为什么需要这些“奇怪的依赖”？(架构揭秘)

为了在没有显示器、没有图形界面的 Linux 服务器上流畅运行明日方舟，我们组合了一套精巧的工具链：

```
       [ 微信通知 / 终端浏览器 ]
                  │ (HTTP / WxPusher)
                  ▼
┌──────────────────────────────────────────────┐
│  Web 控制面板 (web_touch.py)                 │
│  - 纯原生 Python 轻量服务，常驻内存仅 20MB    │
│  - 多账号管理 / 排班可视化 / 实时触摸投屏       │
└──────────────────────┬───────────────────────┘
                       │ 调度与数据
                       ▼
┌──────────────────────────────────────────────┐
│  任务调度流水线 (maa_runner.py / db.py)        │
│  - 账号物理隔离 (独占 Session 存取)            │
│  - 公招每日限额策略 (防乱用加急券)             │
│  - 冲突检测 (多账号时段间隔严格 ≥ 60分钟)      │
└──────────────┬───────────────────────────────┘
               │ ADB 控制
               ▼
┌──────────────────────────────────────────────┐
│  ReDroid (无头 Android 11 容器)              │
│  - 直通 host GPU 硬件加速 (或软解)           │
│  - 通过 binderfs 与宿主内核直接通信          │
└──────────────┬───────────────────────────────┘
               │ 图像与自动化
               ▼
┌──────────────────────────────────────────────┐
│  MAA (MaaAssistantArknights / MaaCore)       │
│  - 高精度 OCR、基建智能换班、1-7 刷理智      │
└──────────────────────────────────────────────┘
```

1. **Docker & Docker Compose**: 实现所有组件的环境隔离，不用把宿主机环境弄得一团糟。
2. **ReDroid (Remote Android)**: 纯容器化的 Android 11 系统。它不是笨重的传统虚拟机（如 VirtualBox/VMware），而是利用 Linux 原生 `binder` 机制直接跑在宿主内核上，**CPU 损耗极低**。
3. **ADB (Android Debug Bridge)**: 负责在宿主机与安卓容器之间发号施令（点击、滑动、输入账密、截屏）。
4. **MAA (MaaAssistantArknights)**: 罗德岛最好的自动化核心！负责图像识别、路线规划、基建排班与作战。
5. **Python 3 内置服务**: 不依赖臃肿的外部重型 Web 框架，单个脚本即可提供高并发 REST API、WebSocket/图片流低延迟投屏与 SQLite 数据库持久化。

## 🌟 核心特性亮点

- 🛡️ **账号真隔离 (Session Level)**: 深度解析 Hypergryph 官方 SDK 机制，每个方舟账号拥有独立的 `shared_prefs` 存档，**绝不串号、绝不污染**。
- 🎯 **全局单点切换交互**: 无论是投屏、改排班、调策略还是查物资，右上角下拉框一键切换，全页面毫秒级响应联动。
- 📋 **公招智能日限额**: 独创公招安全策略——每天按限额（默认 4 次）消耗招聘许可并拉满 9 小时，名额用尽仅收干员刷词条，**绝对禁止加急券**，细水长流。
- 📈 **全物资与芯片看板**: 自动采集合成玉、源石、龙门币、石头，以及 **14 种职业初级/组/双芯片与芯片助剂**，谁缺芯片一目了然。
- 🔔 **多通道通知**: 任务结束后自动生成排版精美的 Markdown 战报，通过 WxPusher 直达微信，支持 SPT 极简推送与 UID 多人分发。
- ⏰ **自适应防撞车排班**: 自动同步系统 Crontab，新增账号时若与其他账号执行时段重叠（<60分钟），自动预警拦截。

## 🚀 快速启动指南

### 1. 检查并准备 Linux 内核 Binder 驱动
```bash
# 检查内核是否已就绪 binderfs
ls -l /dev/binderfs

# 若未就绪，可执行以下命令装载驱动
sudo modprobe binder_linux
sudo mkdir -p /dev/binderfs
sudo mount -t binder binder /dev/binderfs
```

### 2. 克隆项目并初始化配置
```bash
git clone https://github.com/hukaixukai/arknights-server.git
cd arknights-server

# 复制模板配置文件
cp config/accounts.example.json config/accounts.json
cp config/system_settings.example.json config/system_settings.json
cp config/users.example.json config/users.json
```

### 3. 启动安卓模拟器与 Web 交互面板
```bash
# 启动 ReDroid 安卓无头环境
docker compose up -d

# 启动 Web 交互与控制台服务
docker compose -f compose-web.yml up -d
```

打开浏览器访问 `http://你的小主机IP:8090`，即可进入罗德岛指挥中心！

## 🔮 未来扩展与开发设想 (Roadmap)

这个项目的架构设计初衷就是**高度模块化**的——Web 交互层、任务调度层与自动化执行层完全解耦。

* **接入 Mover (基建收益极致化探索)**  
  MAA 的基建换班虽然省心，但在极限跑单、无人机加速策略与特定干员组合的效率压榨上，社区里有更加专业的基建工具（例如 **Mover** 等）。  
  未来我们考虑在执行层抽象出统一的基建引擎接口，**允许用户自由选择用 Mover 替代或协同 MAA 的基建模块**，专门负责无人换班与最优跑单，把小主机的 24 小时基建产出收益拉到极致！  
  *(注：这是一项探索性设想，未来将视社区生态与接口成熟度逐步推进)*
