# 🏰 Arknights Self-Host Hub (明日方舟多账号低功耗自托管服务)

> **“让罗德岛的日常运转，静默发生在家里的低功耗小服务器中。”**  
> 这是一个专为家用 Linux 小主机打造的明日方舟全自动多账号托管系统，集成现代化拟物 Web 控制台、实时触控投屏、多账号物理隔离与全自动化任务调度。

---

## ☕ 写在前面：为什么做这个？

身为罗德岛老博士，每天重复上线清智、换班、公招、逛信用商店，时间久了难免疲惫；可如果交给第三方收费托管平台，账密和登录态交给别人，总让人难以心安。

很多朋友为了用 MAA，常常把家里的 Windows 台式机 24 小时开着挂模拟器，不仅功耗高达几十甚至上百瓦、机箱发热风扇狂转，一个月下来的电费账单也不划算。

其实，现在很多小伙伴家里都常年开着一台低功耗的小机器——可能是闲置的工控机、软路由、轻量 NAS，或者几瓦功耗的小盒子。**既然它本身就 24 小时通电待命，为什么不把明日方舟日常托管在上面呢？**

这个项目就是为了解决这个需求而生。我们希望提供一个清晰完整的开源框架和上手教程，让大家都能直接拿来用，少踩坑、少折腾，算是一点小小的社区贡献！

## 🎯 适合人群与项目定位

### 适合你，如果：
1. **家里有常开的低功耗 Linux 小主机**（软路由、迷你主机、NAS、工控机、旧笔记本等）。
2. **手头有多个明日方舟账号**（自己大号 + 小号，或者帮朋友、亲友一起打理日常）。

### 项目定位：
一个 **轻量、低门槛、模块化、高安全性** 的个人/家庭私有化明日方舟管家，让你彻底告别开着笨重 PC 挂模拟器的烦恼。

## ⚡ 性能占用与最低硬件要求

本项目核心理念是**极致轻量、拒绝臃肿**。平时安卓模拟器完全处于停止休眠状态，只有到了设定的定时任务时段，才会按需自动唤醒，任务跑完秒级释放全部硬件资源。

### 📊 资源开销参考
* **日常待机状态 (99% 的时间)**: Web 控制面板常驻内存仅约 **20 MB**，CPU 占用基本为 **0.0x%**，完全不影响小主机的其他服务（如软路由、NAS、Docker 容器）。
* **任务执行中 (每天集中几次，每次数分钟)**: 自动拉起安卓无头容器与 MAA，内存峰值约 1.8 GB ~ 2.5 GB，CPU 占用约 15% ~ 35%。
* **任务结束即刻**: 模拟器秒级停止，**硬件资源完全回归空闲**。

### 💻 建议最低配置
* **处理器**: 2 核及以上 64 位 x86_64 或 ARM64 处理器
* **内存 (RAM)**: 最低 **4GB**（推荐 8GB 及以上，跑多账号任务更加游刃有余）
* **存储空间**: 预留 25GB 以上可用空间（用于存放安卓系统镜像与游戏本体资源）
* **操作系统**: Linux (Ubuntu 20.04/22.04/24.04, Debian 11/12 等)，内核版本 ≥ 5.4（需支持 `binderfs`）

## 🧩 整体技术架构与依赖说明

为了让游戏在没有显示屏的 Linux 服务器上跑起来，我们组合了这套精巧的开源工具链：

```
       [ 微信通知 / 手机或电脑浏览器 ]
                      │ (HTTPS / WxPusher)
                      ▼
┌──────────────────────────────────────────────┐
│  克拉斐尔 (Cloudflare Tunnel 隧道穿透)       │
│  - 免公网 IP / 免路由端口映射 / 自带 SSL     │
└──────────────────────┬───────────────────────┘
                       │ 本地转发
                       ▼
┌──────────────────────────────────────────────┐
│  Web 控制面板服务 (web_touch.py)             │
│  - 纯原生 Python 轻量服务，常驻内存仅 20MB   │
│  - 多账号管理 / 排班可视化 / 实时触摸投屏      │
└──────────────────────┬───────────────────────┘
                       │ 调度与数据
                       ▼
┌──────────────────────────────────────────────┐
│  任务调度流水线 (maa_runner.py / db.py)       │
│  - 账号物理隔离 (独占 Session 存取)           │
│  - 公招每日限额策略 (防乱用加急券)            │
│  - 冲突检测 (多账号时段间隔严格 ≥ 60分钟)     │
└──────────────┬───────────────────────────────┘
               │ ADB 指令
               ▼
┌──────────────────────────────────────────────┐
│  ReDroid (无头 Android 11 容器)              │
│  - 通过 binderfs 与宿主内核直接通信          │
│  - 极低 CPU 损耗，比传统虚拟机轻快数倍        │
└──────────────┬───────────────────────────────┘
               │ 图像与自动化
               ▼
┌──────────────────────────────────────────────┐
│  MAA (MaaAssistantArknights / MaaCore)       │
│  - 图像识别、智能排班、关卡清智、公招计算    │
└──────────────────────────────────────────────┘
```

1. **Docker & Compose**: 提供整套系统的标准化容器隔离环境。
2. **ReDroid (Remote Android)**: 纯容器化的 Android 11 系统。它利用 Linux 原生的 `binder` 机制直接跑在宿主内核上，摆脱了传统虚拟机（如 VirtualBox/VMware）的巨大开销。
3. **ADB (Android Debug Bridge)**: 宿主机与安卓容器之间点击、输入与控制的桥梁。
4. **MAA (MaaAssistantArknights)**: 罗德岛最强大的自动化核心，负责图像识别与各项事务流转。
5. **Python 3 内置服务**: 不依赖重型 Web 框架，提供低延迟 Web 控制台、触控投屏与 SQLite 数据持久化。

## 🌐 远程访问教程：域名从哪里来？克拉斐尔 (Cloudflare) 怎么托管？

很多人自建服务最大的痛点就是：**人在外面，手机怎么随时查看和控制家里的面板？**  
现在家用宽带普遍没有公网 IPv4，拉宽带开端口映射又麻烦又不安全。我们的最佳解决方案是：**使用自己的域名 + 克拉斐尔 (Cloudflare Tunnel) 进行内网穿透**。

### 1. 域名从哪里来？
- **购买便宜的顶级域名**：前往 NameSilo、Dynadot、腾讯云、阿里云等注册商，购买一个冷门后缀（如 `.cc`、`.top`、`.xyz`、`.work`），第一年往往只要几块钱到十来块钱。
- **配置 DNS 到 Cloudflare**：把域名的 NameServer 修改为 Cloudflare 提供的地址，将域名免费交给 Cloudflare 托管。

### 2. 为什么选择“克拉斐尔” (Cloudflare Tunnel)？
- **零公网 IP 要求**：不管你是大内网宽带、移动宽带还是手机热点，只要小主机能上网，就能穿透出来。
- **免去路由器端口映射**：不用动路由器任何设置，安全防扫描。
- **自带全球 CDN 与免费 HTTPS**：自动签发合规 SSL 证书，数据传输全链路加密。
- **搭配 Cloudflare Zero Trust (完全免费)**：个人免费计划完全足够自建使用。

### 3. 克拉斐尔穿透实战配置
1. 登录 [Cloudflare Zero Trust 控制台](https://one.dash.cloudflare.com/)；
2. 进入 **Networks** -> **Tunnels**，点击 **Create a Tunnel**（创建隧道）；
3. 复制生成的 `cloudflared` 安装命令并在你的 Linux 小主机上运行，或者直接用 Docker 运行 `cloudflared`：
   ```bash
   docker run -d --name cloudflare_tunnel --restart=always \
     cloudflare/cloudflared:latest tunnel --no-autoupdate run --token <你的TUNNEL_TOKEN>
   ```
4. 在 Cloudflare 面板的 **Public Hostname** 中添加一条规则：
   * **Domain / Subdomain**: 输入你想要的二级域名（例如 `ark.yourdomain.com`）
   * **Type**: `HTTP`
   * **URL**: `localhost:8090`（即本项目 Web 面板的本地监听端口）
5. 点击保存！现在你在手机浏览器输入 `https://ark.yourdomain.com`，就能在全世界随时随地安全直达你的方舟控制中心了！

## 🛠️ 快速上手部署指南

### 第一步：准备 Linux 内核 Binder 驱动
ReDroid 运行需要内核开启 `binderfs`。执行以下命令检查：
```bash
ls -l /dev/binderfs
```
若提示目录不存在，可加载内核模块并挂载：
```bash
sudo modprobe binder_linux
sudo mkdir -p /dev/binderfs
sudo mount -t binder binder /dev/binderfs
```
*(可以将以上命令加入系统的 `/etc/rc.local`，确保开机自启)*

### 第二步：克隆项目与初始化配置
```bash
git clone https://github.com/hukaixukai/arknights-server.git
cd arknights-server

# 从模板创建配置文件
cp config/accounts.example.json config/accounts.json
cp config/system_settings.example.json config/system_settings.json
cp config/users.example.json config/users.json
```

### 第三步：一键拉起服务
```bash
# 启动 ReDroid 安卓无头容器
docker compose up -d

# 启动 Web 交互面板
docker compose -f compose-web.yml up -d
```

服务就绪后，在局域网浏览器输入 `http://<小主机IP>:8090`，即可进入登录界面！

## 🌟 核心功能特性

- 🛡️ **Session 级账号真隔离**: 深度适配 Hypergryph 官方 SDK 机制，每个方舟账号拥有独立的 `shared_prefs` 存档，**绝不串号、绝不相互污染**。
- 🎯 **右上角全局唯一切换中心**: 投屏、排班调整、作战关卡设定、物资芯片查阅，全部收归右上角下拉框，全界面毫秒级响应联动。
- 📋 **公招每日限额策略**: 每天按限额（默认 4 次）消耗招聘许可并拉满 9 小时，名额用尽仅收干员刷词条，**严格禁止乱花加急券**。
- 📈 **全物资与芯片储备大屏**: 实时同步合成玉、源石、龙门币、固源岩，以及 **14 种职业初级/组/双芯片与芯片助剂**。
- 🔔 **多通道消息分发**: 任务完成后生成精美的 Markdown 报告，直达微信（支持 WxPusher 极简 SPT 与多 UID 分发）或电子邮箱。
- ⏰ **智能防撞车动态排班**: 自动同步系统 Crontab，新增账号时若与其他账号执行时段重叠（<60分钟），自动预警拦截。
